<Callout type="info">

Quickly copy an XPath with DevTools:

1. Right‑click the target element (button, link, input) and choose Inspect.
2. In the Elements panel, ensure the element is highlighted.
3. Right‑click the highlighted node and choose Copy → Copy XPath.
4. Paste the XPath into the step Target field.

</Callout>

<Callout type="info">

The Target field is checked as you save. An empty Target, or one that is not a valid XPath, selector or regular expression, shows a warning under the field because the automation would stop at that step. Targets that are only known when the automation runs (Google Sheets values, placeholders such as `<batchRepeat>`) are not checked.

If a Target stops matching later because the page changed, you can pick the element again from the status bar instead of rewriting it here. See [Fix Element Not Found]([[docsref:/step/fix-not-found]]).

</Callout>

### Plain text

<AddedIn version="5.8.0" />

In a new step you can name the element the way you would describe it, with no prefix and no XPath. Type what the field is called or what the button says.

| You type                 | What it matches                                                                                                              |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| `email`                  | Anything whose name, label or other attribute **contains** "email". If nothing matches, the text is tried as a CSS selector. |
| `"email"`                | Only what is **exactly** "email".                                                                                            |
| `/^e-?mail$/i`           | A regular expression.                                                                                                        |
| `//input[@name="email"]` | XPath, as always.                                                                                                            |

The text is compared with these attributes of each field and button:

- `name`, `id`
- `autocomplete` (except `on` and `off`), for example `given-name` or `postal-code`
- the field's label
- `aria-label`, `placeholder`, `title`
- the visible text of buttons and links
- `value`, for checkboxes, radio buttons and button inputs only
- `class`, `ng-model`, `data-bind`, `data-reactid`, `aria-describedby`

Matching ignores upper and lower case. Use a regular expression when case matters.

```html
<form>
  <label for="fn">First name</label>
  <input id="fn" name="first_name" autocomplete="given-name" /> 👈 First name, first_name, "given-name" <input name="email" placeholder="you@example.com" /> 👈 email <input name="confirm_email" /> 👈
  confirm, "confirm_email" <button type="submit">Create account</button> 👈 Create account
</form>
```

#### With and without quotes

Without quotes, the text only has to be contained, and the closest matches win: elements that are exactly the text come first, then those that start with it, then those that contain it. In the form above, `email` fills the `email` field and leaves `confirm_email` alone.

With quotes, only an exact match counts. If the `email` field is ever removed from the page, `email` would move on to `confirm_email`, while `"email"` stops with "element not found". Use quotes when filling the wrong field would be worse than stopping.

#### When several elements match

The step runs against every match, the same as an XPath that matches several elements. `Like` clicks every button labelled "Like" and does not touch "Unlike".

If both visible and hidden elements match, only the visible ones are used. Pages often keep a hidden mobile copy of a desktop button.

To act on fewer elements, make the text more specific, add quotes, or use an XPath.

<Callout type="info">

Plain text works in steps created in version 5.8.0 or later. A step created before that keeps reading its Target as an XPath, even after you edit it, so nothing you already have changes. To use plain text in an older automation, add a new step.

Prefixes such as `#id`, `Selector::` and `Name::`, and XPath, work the same in old and new steps.

</Callout>

<Callout type="info">

Two forms from other tools are also understood: `text=View Form`, which is the same as typing `View Form`, and `button:has-text("Confirm")`, which matches buttons containing that text. Other selectors from those tools are not supported.

</Callout>

### Get element by ID

When an element has an id attribute (for example, `id="idValue"`), you can target it with `#idValue` or `Id::idValue`.

Notes:

- IDs are intended to be unique. If duplicates exist, the first match is selected.

<Callout type="info">Referring to the HTML below: - `#inputEmail` targets `id="inputEmail"`. - `#inputPassword` targets `id="inputPassword"`.</Callout>

```html
<main class="form-signin">
  <form>
    <label for="inputEmail">Email address</label>
    <input type="email" id="inputEmail" class="form-control" /> 👈 selected
    <label for="inputPassword">Password</label>
    <input type="password" id="inputPassword" class="form-control" /> 👈 selected
    <button class="btn btn-primary" type="submit">Sign in</button>
  </form>
</main>
```

### Get elements by class name

When an element has a class list (for example, `class="class-1 class-2"`), target it with `ClassName::class-1 class-2`.

Notes:

- This selector can match multiple elements. The step runs against each match.

<Callout type="info">
Referring to the HTML below:
- `ClassName::form-control` targets `class="form-control"` inputs.
- `ClassName::btn btn-primary` targets `class="btn btn-primary"` buttons.
</Callout>
```html
<main class="form-signin">
  <form>
    <label for="inputEmail">Email address</label>
    <input type="email" id="inputEmail" class="form-control"> 👈 selected
    <label for="inputPassword">Password</label>
    <input type="password" id="inputPassword" class="form-control"> 👈 selected
    <button class="btn btn-primary" type="submit">Sign in</button> 👈 selected
  </form>
</main>
```

### Get elements by name

When an element has a name attribute (for example, `name="email"`), target it with `Name::email`.

Notes:

- This selector can match multiple elements. The step runs against each match.

<Callout type="info">
Referring to the HTML below:
- `Name::email` targets `name="email"`.
- `Name::password` targets `name="password"`.
</Callout>
```html
<main class="form-signin">
  <form>
    <label for="inputEmail">Email address</label>
    <input type="email" id="inputEmail" class="form-control" name="email"> 👈 selected
    <label for="inputPassword">Password</label>
    <input type="password" id="inputPassword" class="form-control" name="password"> 👈 selected
    <button class="btn btn-primary" type="submit">Sign in</button>
  </form>
</main>
```

### Get elements by tag name

To target all elements of a given tag, use `TagName::tagNameOfElement`.

Notes:

- This selector matches all elements with the specified tag. The step runs against each match.

<Callout type="info">
Referring to the HTML below:
- `TagName::main` targets `<main>`.
- `TagName::form` targets `<form>`.
- `TagName::input` targets `<input>`.
- `TagName::label` targets `<label>`.
- `TagName::button` targets `<button>`.
</Callout>
```html
<main class="form-signin">
  <form>
    <label for="inputEmail">Email address</label>
    <input type="email" id="inputEmail" class="form-control" name="email">
    <label for="inputPassword">Password</label>
    <input type="password" id="inputPassword" class="form-control" name="password">
    <button class="btn btn-primary" type="submit">Sign in</button>
  </form>
</main>
```

### Query Selector (single)

To target a specific element by CSS selector, use `Selector::selector`.

Notes:

- Selects the first matching element. If multiple elements match, only the first is used.
- If no match is found in the main document, open shadow roots are also searched.

<Callout type="info">
Referring to the HTML below:
- `Selector::main.form-signin` targets `<main class="form-signin">`.
- `Selector::form` targets `<form>`.
- `Selector::input[type="email"]` targets `<input type="email">`.
- `Selector::input[type="password"]` targets `<input type="password">`.
- `Selector::label[for]` targets `<label for="…">`.
- `Selector::button.btn.btn-primary` targets `<button class="btn btn-primary">`.
</Callout>
```html
<main class="form-signin">
  <form>
    <label for="inputEmail">Email address</label>
    <input type="email" id="inputEmail" class="form-control" name="email">
    <label for="inputPassword">Password</label>
    <input type="password" id="inputPassword" class="form-control" name="password">
    <button class="btn btn-primary" type="submit">Sign in</button>
  </form>
</main>
```

### Query Selector All (multiple)

To target all matching elements by CSS selector, use `SelectorAll::selector`.

<Callout type="warning">Important: Works like Query Selector, but selects all matching elements instead of only the first one. The step is applied to each matched element.</Callout>

### Find By Position

To target the top-most element at specific viewport coordinates, use `Position::x,y`.

Notes:

- Coordinates use viewport pixels (same behavior as `document.elementFromPoint(x, y)`).
- Coordinates are affected by page scroll and zoom.
- If no element is present at that point, retry behavior follows your step settings.
- `ClickAt::x,y` and `ElementFromPoint::x,y` are still supported for backward compatibility.

Examples:

- `Position::395,452`
- `Position::120.5,300`

## Dynamic XPath

<Callout type="info">
- [loop-repeat]([[docsref:/automation/loop#repeat]]): iterate over rows using a placeholder in the XPath. For example, to click the button in each row: base XPath `//table/tr[1]/td[1]/button` → `//table/tr[<loopRepeat>]/td[1]/button`.
- [step-repeat]([[docsref:/step/overview#repeat]]): iterate over columns or repeated targets within a row. Example: `//table/tr[1]/td[<stepRepeat>]/button`.
- [session-count]([[docsref:/step-value/session]]): refer to the current session number. Example: `//table/tr[1]/td[<sessionCount>]/button`.
</Callout>
